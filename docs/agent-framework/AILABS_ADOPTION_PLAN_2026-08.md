## 0. The finding that matters most

CARSI carries **23 skill files that no agent runtime loads.**

`skills/**/**.skill.md` uses a bespoke schema (`category`, `version`, `auto_load`, `priority`,
`triggers`, `requires`). The Agent Skills open standard — the format Claude Code, Codex, Cursor,
Copilot and VS Code all read — requires a directory named for the skill containing `SKILL.md`,
with frontmatter drawn from exactly six fields (`name`, `description`, `license`,
`compatibility`, `metadata`, `allowed-tools`).

- Spec: <https://agentskills.io/specification>
- Claude Code: <https://code.claude.com/docs/en/skills> — reads `.claude/skills/<name>/SKILL.md`
- Codex: <https://developers.openai.com/codex/skills/> — reads `.agents/skills/<name>/SKILL.md`

Consequences today:

| | Count |
|---|---|
| Real Agent Skills in the repo, before this branch | **1** (`.claude/skills/carsi-course-production`) |
| Real Agent Skills after this branch | **2** (adds `.claude/skills/carsi-verification-gate`) |
| Bespoke `*.skill.md` files never auto-loaded | **23** |
| `.claude/settings.json` | absent |
| `.claude/agents/` (subagent definitions) | absent |
| `.claude/workflows/` | absent |
| Hooks | none configured |

The drift is already visible internally: `skills/INDEX.md` claims 38+ skills and lists
`tailwind.skill.md` and `components.skill.md`, **neither of which exists** — a gap
`docs/agent-framework/GAP-BACKLOG-2026-08-07.md` already flagged. A registry nothing loads cannot
self-correct.

This is not a documentation problem. It is the difference between procedures that sit in a folder
and procedures an agent actually follows.

## 1. Convert `skills/` to the Agent Skills standard  *(highest value, low risk)*

**Target layout**

```
.claude/skills/
  carsi-course-production/SKILL.md   # exists
  carsi-verification-gate/SKILL.md   # added on this branch — worked example
  carsi-design-system/SKILL.md
  carsi-australian-context/SKILL.md
  carsi-nextjs-patterns/SKILL.md
  carsi-search-authority/SKILL.md
  ...
```

**Rules to author against** (all from Anthropic's own best-practices page,
<https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices>):

- `name` must match the parent directory, lowercase `a-z0-9-`, and **cannot contain "claude" or
  "anthropic"**.
- `description` is the only thing in context until the skill triggers — write it in **third
  person**, state **what it does AND when to use it**, and include the words the team actually
  says. This is how Claude selects among skills.
- **Under 500 lines.** Push detail into `references/` **one level deep** only.
- Prefer gerund names (`writing-server-actions`) over noun soup.
- "Every line is a recurring token cost. State what to do rather than narrating how or why."

**Portability rule.** Use **only the six spec fields** in anything shared. Claude Code accepts
extras (`paths`, `context: fork`, `model`, `effort`, `disable-model-invocation`), but claude.ai
uploads and the Skills API **hard-error** on them. Keep the canonical skill in `.claude/skills/`
and symlink into `.agents/skills/` if Codex parity is wanted.

**Migration order** (by leverage, not by folder):

1. `verification/*` → `carsi-verification-gate` — **done on this branch**
2. `australian/australian-context` → `carsi-australian-context` (licence-adjacent, applies broadly)
3. `design/design-system` + `design/foundation-first` → `carsi-design-system`
4. `frontend/nextjs` → `carsi-nextjs-patterns`
5. `search-dominance/*` → `carsi-search-authority`
6. `context/orchestration` → **delete, do not migrate.** It describes a hand-rolled router that
   Claude Code's own subagent/workflow primitives now supersede (§3).

Retire `skills/INDEX.md` at the end of the migration — the skill listing is generated by the
runtime from `description` fields, and a hand-maintained index will always drift.

## 2. Make the licence-critical guards deterministic, not advisory

CARSI already has the hard part: `check:iicrc-terminology`, `check:iicrc-compliance`,
`check:designations`, `check:cec`, `check:cec-surfaces`, `check:standards-claims`,
`check:au-english`, `check:sources`. What is missing is a mechanism that makes an agent unable
to finish a turn while one of them fails.

`check:iicrc-compliance` must be in that list and in whatever Stop hook enforces it: CLAUDE.md
names it and `check:iicrc-terminology` as the two guards that must never be weakened, so a
suite that omits it silently drops half the systemic backstop. Note also that `check:sources`
is advisory — it exits 0 on warnings, so an enforcing hook must either pass `--enforce` or not
count it as a gate.

Anthropic documents four escalating enforcement tiers
(<https://code.claude.com/docs/en/best-practices>):

| Tier | Mechanism | Use for |
|---|---|---|
| 1 | In-prompt iteration | Ad-hoc work |
| 2 | `/goal` condition, re-checked by an evaluator each turn | Bounded autonomous passes |
| 3 | **Stop hook** — blocks the turn from ending until a script passes | **Licence-critical guards** |
| 4 | Adversarial review subagent in fresh context | Pre-release sweeps |

**Recommendation: tier 3 for the CEC/IICRC guards.** They are the checks where a false pass costs
the licence to sell courses. A Stop hook in `.claude/settings.json` running the guard suite turns
"the agent should have run this" into "the agent could not stop without running this." Note the
documented escape valve: Claude Code overrides a Stop hook after 8 consecutive blocks, so the hook
must fail *fast and legibly*, not loop.

Caveat for `/goal` (tier 2): the evaluator **cannot run commands or read files** — it only judges
what is already in the transcript (<https://code.claude.com/docs/en/goal>). Goal conditions must
therefore be phrased so the evidence appears in Claude's own output, e.g. *"`npm run
check:iicrc-terminology` has been run and its exit output pasted, showing 0 violations."*

## 3. Replace the hand-rolled orchestrator with documented primitives

`skills/context/orchestration.skill.md` describes a bespoke "master coordinator routing to
specialized agents" pattern. Claude Code now ships four primitives that cover this, and the
official guidance is to choose by asking **who holds the plan**
(<https://code.claude.com/docs/en/agents>):

| Who holds the plan | Primitive | Fit for CARSI |
|---|---|---|
| Claude, turn by turn | **Subagents** (`.claude/agents/*.md`) | Course-content review, security review |
| Claude, following instructions | **Skills** | The migrated `skills/` content |
| A lead agent supervising peers | Agent teams (experimental) | Not yet |
| **The script** | **Dynamic workflows** (`.claude/workflows/`) | Catalogue-wide audits, content sweeps |

Concrete first targets:

- **Subagent definitions** in `.claude/agents/`: `carsi-content-reviewer` (Australian-production +
  CEC terminology, read-only), `carsi-security-reviewer` (auth on admin routes, bounded
  `findMany`). Both should carry `isolation: worktree` if they write.
- **A dynamic workflow** for catalogue-wide passes — e.g. auditing every catalogue course for
  CEC-claim leakage. Derive the fan-out from `data/seed/courses-catalog.json` at run time rather
  than hard-coding a total; it currently holds 37 courses (24 published, 13 draft) and moves. Two documented rules govern the design:
  - **Fan out across many short agents, never a few long ones.** On resume, cached results stop at
    the first agent that did not finish and *everything started after it re-runs*.
  - **No mid-run user input.** Founder sign-off must be modelled as separate workflows:
    `/cec-audit` → review → `/cec-fix` → review → `/cec-verify`.
  - Limits: **up to** 16 concurrent (fewer on fewer CPUs, including in CPU-limited CI containers),
    1,000 agents per run, subagents always run in `acceptEdits`. Resume works only within the same
    session — exiting Claude Code restarts the workflow fresh.
  - <https://code.claude.com/docs/en/workflows>

## 4. Design system: make it queryable, not readable

Meta's **Astryx** (18 June 2026, MIT, <https://github.com/facebook/astryx>) is the first major
design system built on the premise that the primary consumer is an agent. CARSI should **not**
migrate to it — Astryx is React 19 + StyleX, CARSI is Tailwind 4 + Radix. Three patterns transfer
for free:

1. **A machine-readable component inventory** the skill instructs the agent to consult *before*
   authoring UI, so it reuses existing variants instead of inventing a third button.
2. **Token-dense docs output** rather than prose (Astryx's `--dense` flag).
3. **Generate the agent rule file from the design system**, rather than hand-maintaining it
   (Astryx's `init --features agents`).

The `carsi-design-system` skill should carry the rules an agent *cannot infer* from the CSS —
e.g. that brand tokens are space-separated RGB triples consumed via `rgb(var(--carsi-blue) /
<alpha>)`, that shadcn tokens are HSL triples, and that dark mode is class-based via `.dark` and
never `prefers-color-scheme`.

**Close the visual loop with what already exists.** `e2e/a11y.spec.ts` and the Playwright suite are
in place; adding screenshot assertions makes the compare step an agent-legible pass/fail signal.
Anthropic's documented prompt for design work is worth using verbatim: *"implement this design.
take a screenshot of the result and compare it to the original. list differences and fix them."*
Keep a11y in the same gate — screenshot loops optimise appearance and are blind to semantic HTML
and keyboard navigation.

## 5. Model and prompt hygiene

- **Audit every prompt and skill for "reflect", "show your thinking", "explain your reasoning".**
  On Claude Fable 5 these trigger the `reasoning_extraction` refusal category and cause silent
  fallbacks to Opus 4.8.
  <https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5>
- **Refusals return HTTP 200 with `stop_reason: "refusal"`,** not an error. Any CARSI code path
  calling the API directly must handle this explicitly or it will read a refusal as a successful
  empty response.
- **Delete enumerate-every-behaviour prompt scaffolding.** Both Anthropic and OpenAI now document
  that prompt libraries written for the previous model generation are a net negative. Describe the
  destination; invest in success criteria and verification loops instead of longer prompts.
- **If Codex is used alongside Claude Code:** the `gpt-5.6` alias defaults to Sol (the most
  expensive variant). Pin Terra or Luna for cost-sensitive work, and on migration test one
  reasoning-effort level *lower* than the current baseline — OpenAI's own recommended step.
  <https://developers.openai.com/api/docs/guides/prompt-guidance-gpt-5p6>

## 6. Bridge `AGENTS.md`

`docs/AGENTS.md` exists but Claude Code reads `CLAUDE.md` only. The documented bridge is an
import on the first line of `CLAUDE.md`. Write it as **`@docs/AGENTS.md`** — imports resolve
relative to the file that contains them, and there is no `AGENTS.md` at the repo root, so
`@AGENTS.md` would resolve to a file that does not exist. It fails silently: nothing is loaded
and no error is raised, so the bridge looks wired while the content never reaches context.
(Create a root `AGENTS.md` symlink to `docs/AGENTS.md` first if the shorter form is wanted.)
<https://code.claude.com/docs/en/memory>

`CLAUDE.md` is currently 159 lines — inside Anthropic's "under 200 lines" guidance. Keep it there:
as skills absorb the procedural content, the licence-critical *facts* stay in `CLAUDE.md` and the
*procedures* move out.

## What was deliberately *not* recommended

- **Adopting Astryx.** Wrong stack (StyleX vs Tailwind), beta at v0.1.6.
- **Adopting Buzz.** Its workflow approval gates are unfinished by Block's own README, and
  Block-hosted communities are not end-to-end encrypted. Not for production source.
- **Installing Hermes Agent.** Its useful primitive — `claude -p '<task>' --allowedTools 'Read,Edit'
  --max-turns 10 --output-format json` for CI — is just Claude Code CLI flags and is adoptable
  without it. The installer is `curl | bash` with a `terminal` tool; if evaluated, run it in a
  container against a clone, never against production credentials.
- **"Fleet engineering" and "graph engineering" as architectural vocabulary.** Neither is an
  Anthropic term; searching for documentation on them wastes time. The real primitives are
  subagents → agent view → agent teams → dynamic workflows.
